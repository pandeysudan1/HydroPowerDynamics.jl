# FCR prequalification study

This folder turns the report workflow into one executable engineering study using `HydroPowerDynamics.jl`, `ControlSystemsBase.jl`, `JuMP.jl` and `Ipopt.jl`.

## Purpose

The objective is to reduce the repeated manual work around FCR prequalification by separating the workflow into four reusable layers:

1. **Nonlinear physics** - HydroPowerDynamics.jl hydraulic, turbine and governor equations.
2. **Linear screening** - local/reduced state-space model and frequency-domain checks.
3. **Capacity search** - JuMP maximizes the offered FCR reserve subject to dynamic and plant constraints.
4. **Nonlinear verification** - the optimized candidate is replayed on the nonlinear HPD plant and returned as `PASS` or `REDUCE / RETUNE` with diagnostic quantities.

The optimizer does **not** make an official qualification decision. Product-specific Nordic/Statnett test trajectories, operating points, envelopes, measurement-path requirements and reporting rules remain an external qualification-data layer.

## Main notebook

- `FCR_Prequalification_Study.jl` - Jupytext source of the notebook.
- `FCR_Prequalification_Study.ipynb` - executed notebook generated by CI, including plots and printed outputs.

The notebook runs this chain:

```text
Trollheim-inspired HPD operating point
        |
        v
Reduced linear model -> Bode / phase / Nyquist
        |
        v
JuMP + Ipopt: maximize P_FCR
  subject to gate, gate-rate,
  flow and delivery constraints
        |
        v
Map P_FCR* to droop R*
        |
        v
Nonlinear HPD prescribed-frequency test
        |
        v
PASS / REDUCE / RETUNE
```

## Current test definition

The first executable version intentionally uses a **proxy** FCR test configuration so the optimization can be inspected end-to-end. The numerical proxy settings are collected in the notebook and are not presented as current Statnett regulatory limits.

The next qualification step is to replace the proxy configuration with current FCR-N/FCR-D test data while keeping the plant and optimization architecture unchanged.

## Reproduce locally

```bash
julia --project=. -e 'using Pkg; Pkg.resolve(); Pkg.instantiate()'
pip install jupytext nbconvert jupyter
julia -e 'using Pkg; Pkg.activate(temp=true); Pkg.add("IJulia"); using IJulia; installkernel("Julia 1.11", "--project=$(pwd())")'
jupytext --to ipynb quick_examples/fcr_prequalification_study/FCR_Prequalification_Study.jl
jupyter nbconvert --to notebook --execute --inplace \
  quick_examples/fcr_prequalification_study/FCR_Prequalification_Study.ipynb \
  --ExecutePreprocessor.timeout=1800
```

## Engineering interpretation

The useful output is not only the maximum reserve `P_FCR*`. The study also records the limiting constraint and the mismatch between the reduced screening model and nonlinear physics. That is what makes the workflow useful for low-cost prequalification preparation: a failed candidate can be traced to actuator rate, hydraulic capability, response delivery or model/controller assumptions rather than returning only a Boolean result.
